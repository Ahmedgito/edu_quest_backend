👨‍🎓 STUDENT EXPERIENCE (End User Perspective)

I want students to feel like this platform is built specifically for them — simple, guided, and reliable.

🔹 1. First Interaction (Exploration Without Commitment)

A student should be able to:

Visit the platform and immediately browse competitions
See only relevant competitions based on their grade
Filter competitions easily (by subject, grade, etc.)

They should NOT be forced to sign up just to explore.

👉 The platform should first attract, then convert

🔹 2. Decision Point (Interest → Action)

When a student decides to join a competition:

If they are not logged in → the system should ask them to log in
After login → they should return to the same competition they selected

This avoids frustration and keeps the flow natural.

🔹 3. Account Creation

When a student signs up:

The process should be quick and simple
Their account should become active immediately
No manual approval required

After login:

They should land directly on their personal dashboard
🔹 4. Joining a Competition (Core Interaction)

When a student joins:

The system must confirm clearly that registration is successful
The same competition should not be joinable again

The system must also ensure:

The competition is still open
The student is eligible (correct grade)

👉 This step must be reliable and controlled, not just a button click

🔹 5. Student Dashboard (Daily Use Area)

The dashboard should clearly separate:

A. My Competitions
Shows everything the student is part of:
Self-joined competitions
Competitions added via school
B. Available Competitions
Only shows:
Competitions matching the student’s grade
Competitions not already joined
Active competitions only
🔹 6. Profile Management

Students should:

Be able to update personal contact details

But they should NOT:

Change their grade
Change their school

👉 This prevents manipulation and keeps the system fair

🔹 7. Expected Outcome

A student should feel:

👉 “I can easily find, join, and track competitions without confusion.”

🏫 SCHOOL EXPERIENCE (Operational User Perspective)

The school is not a casual user — it’s an operational entity.
The system should prioritize efficiency + control.

🔹 1. Registration & Trust Barrier

When a school registers:

Their account should NOT be instantly usable
It should go into a pending state

The system must clearly communicate:
👉 “Your account is awaiting approval”

🔹 2. Approval Dependency

Until approval:

The school should not be able to perform key actions

After approval:

Full access should be granted immediately

👉 This creates a trust-controlled ecosystem

🔹 3. Bulk Student Management (Core Feature)

This is the most critical part for schools.

The school should:

Download a predefined template
Fill student data offline
Upload it in one action

The system should:

Process each student individually
Create accounts automatically
Link them to the school
🔹 4. Smart Error Handling

The system must NOT behave like a black box.

If issues occur:

It should clearly identify problematic entries
Allow valid data to still go through

👉 Example expectation:

“80 students added successfully, 20 failed with reasons”
🔹 5. Visibility & Control

The school should be able to:

View all registered students
See which competitions each student is part of
🔹 6. Controlled Permissions

The school should NOT have full control over everything:

Sensitive fields (like grade) should be restricted
System integrity should not depend on school honesty
🔹 7. Expected Outcome

The school should feel:

👉 “This system allows us to manage hundreds of students efficiently without manual effort.”

🧑‍💼 ADMIN EXPERIENCE (System Owner Perspective)

The admin is responsible for governance, control, and system integrity.

🔹 1. System Overview

When the admin logs in:

They should immediately see:
Total schools
Total students
Active competitions

👉 This is for quick monitoring and decision-making

🔹 2. School Governance (Critical Control Layer)

The admin must:

View all registered schools
Approve or reject them

If needed:

Revoke access even after approval

👉 This ensures only trusted entities operate in the system

🔹 3. Competition Management (Core System Engine)

The admin should:

Create competitions with full details
Make them visible to students instantly

They should also be able to:

Edit competitions
Remove competitions

👉 Competitions are the core product offering, so control must be strong

🔹 4. Participant Oversight

The admin should:

View all participants in a competition
Remove participants if required

👉 This ensures moderation and fairness

🔹 5. Student Oversight

The admin should:

View all students in the system
Remove invalid or problematic entries
🔹 6. Authority & Intervention

The admin should always have:

Final authority over all data
The ability to intervene in any scenario

👉 No part of the system should be uncontrollable

🔹 7. Expected Outcome

The admin should feel:

👉 “I have full visibility and control over the entire platform and can manage it confidently.”

🧠 SYSTEM-WIDE EXPECTATIONS
🔹 Data Integrity
No duplicate students
No duplicate competition entries
Clean and consistent data across the system
🔹 Controlled Access
Students → open access
Schools → approval-based access
Admin → full control
🔹 Consistency
Actions should always give feedback
No silent failures
No confusing states
🔹 Reliability

Every important action should:

Be validated
Be confirmed
Be reflected immediately in the system
